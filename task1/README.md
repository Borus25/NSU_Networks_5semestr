# Multicast Discovery

Приложение обнаруживает другие запущенные копии в одной локальной сети с помощью **UDP multicast**.

Каждый экземпляр программы:

- подписывается на заданную multicast-группу через выбранный сетевой интерфейс;
- раз в секунду отправляет heartbeat с уникальным `instance_id`;
- принимает heartbeat других экземпляров;
- хранит IP-адрес и время последнего сообщения каждой копии;
- выводит список при появлении, исчезновении или изменении адреса копии;
- удаляет копию из списка, если от неё нет сообщений более 3 секунд.

## Структура проекта

```text
.
├── go.mod
├── go.sum
├── main.go
├── multicast.go
├── heartbeat.go
├── peers.go
└── README.md
```

Назначение файлов:

- `main.go` — разбор аргументов, проверка адреса и интерфейса, создание сокета, запуск и завершение приложения;
- `multicast.go` — подписка на группу, выбор исходящего интерфейса, включение multicast loopback, настройка IPv4 TTL или IPv6 Hop Limit;
- `heartbeat.go` — отправка и приём heartbeat-сообщений;
- `peers.go` — таблица найденных копий, обработка таймаутов и вывод списка.

Все `.go`-файлы должны находиться в одном каталоге и использовать `package main`.

## Требования

- Go 1.26 или новее (я делал на 1.27)
- Linux, macOS или Windows с поддержкой IPv4/IPv6 multicast;
- все проверяемые устройства должны находиться в одной локальной сети;
- firewall должен разрешать входящий и исходящий UDP-трафик на выбранном порту;
- Wi-Fi-точка доступа не должна изолировать клиентов и блокировать multicast.

Проверить версию Go:

```bash
go version
```

## Подготовка проекта

Перейдите в каталог, содержащий исходные файлы:

```bash
cd ~/GolandProjects/Networks
```

Если `go.mod` уже есть, достаточно загрузить и проверить зависимости:

```bash
go mod tidy
```

Если `go.mod` ещё не создан, выполните:

```bash
go mod init multicast-discovery
go get golang.org/x/net/ipv4
go get golang.org/x/net/ipv6
go mod tidy
```

Проект использует пакеты `golang.org/x/net/ipv4` и `golang.org/x/net/ipv6` для настройки multicast-интерфейса, loopback и TTL/Hop Limit.

## Сборка

Собирать нужно **весь пакет**, а не отдельный файл:

```bash
go build -o discovery .
```

После успешной сборки в текущем каталоге появится исполняемый файл `discovery`.

## Формат запуска

```text
./discovery MULTICAST_IP INTERFACE PORT
```

Аргументы:

| Аргумент | Назначение | Пример |
|---|---|---|
| `MULTICAST_IP` | IPv4- или IPv6-адрес multicast-группы | `239.10.10.10`, `ff02::1234` |
| `INTERFACE` | Имя сетевого интерфейса, через который выполняются подписка и отправка | `wlp2s0`, `eth0`, `enp3s0` |
| `PORT` | Общий UDP-порт от 1 до 65535 | `9999` |

Все экземпляры, которые должны обнаруживать друг друга, должны использовать **одинаковые группу и порт**. Интерфейс выбирается отдельно на каждом устройстве и поэтому может называться по-разному.

## Поиск интерфейса

### Linux

```bash
ip -brief link
ip -brief address
```

Пример вывода:

```text
lo               UNKNOWN        127.0.0.1/8 ::1/128
wlp2s0           UP             192.168.1.25/24 fe80::1234/64
```

Для обмена с другими устройствами выбирайте активный Wi-Fi- или Ethernet-интерфейс, например `wlp2s0` или `enp3s0`.

### macOS

```bash
ifconfig
```

Чаще всего Wi-Fi-интерфейс называется `en0`.

### Windows PowerShell

```powershell
Get-NetAdapter
Get-NetIPAddress
```

При запуске передавайте имя интерфейса в том виде, который ожидает текущая реализация программы.

## Проверка IPv4

В примерах используется administratively scoped IPv4 multicast-группа `239.10.10.10` и UDP-порт `9999`.

### Две копии на одном компьютере

В первом терминале:

```bash
./discovery 239.10.10.10 wlp2s0 9999
```

Во втором терминале:

```bash
./discovery 239.10.10.10 wlp2s0 9999
```

Замените `wlp2s0` на имя активного интерфейса. Благодаря включённому multicast loopback локальные экземпляры могут получать multicast-пакеты друг друга через выбранный интерфейс.

### Два устройства в одной сети

На первом устройстве:

```bash
./discovery 239.10.10.10 wlp2s0 9999
```

На втором устройстве, где интерфейс может называться иначе:

```bash
./discovery 239.10.10.10 wlan0 9999
```

Устройства должны быть подключены к одной локальной сети. После получения heartbeat программа выведет найденную копию, например:

```text
Found live copies: 1:
    192.168.1.26 - 7295138794530123456
```

При запуске трёх экземпляров каждый из них должен показать две другие копии. Собственный heartbeat отбрасывается по совпадению `instance_id`.

Остановите один экземпляр сочетанием `Ctrl+C`. Примерно через 3–4 секунды оставшиеся экземпляры удалят его из таблицы и снова выведут изменившийся список.

## Проверка IPv6

Для link-local multicast используйте адрес со scope `ff02::/16`, например `ff02::1234`:

```bash
./discovery ff02::1234 wlp2s0 9999
```

На другом устройстве:

```bash
./discovery ff02::1234 wlan0 9999
```

Для link-local IPv6 один и тот же адрес может существовать на нескольких интерфейсах, поэтому программа задаёт `Zone` через выбранный интерфейс. Например, логически адрес назначения имеет вид:

```text
[ff02::1234%wlp2s0]:9999
```

Проверьте, что на интерфейсе есть IPv6 link-local адрес:

```bash
ip -6 addr show dev wlp2s0
```

В выводе должен присутствовать адрес, начинающийся с `fe80::`.

## Ограничение области рассылки

Программа явно устанавливает:

- IPv4 multicast TTL: `1`;
- IPv6 multicast Hop Limit: `1`.

Поэтому пакеты предназначены только для текущего локального сегмента и не должны маршрутизироваться в другие подсети. Это ожидаемое поведение лабораторной работы.
