# Места — асинхронное сетевое взаимодействие

Лабораторная работа по компьютерным сетям: поиск локаций, получение текущей погоды и поиск объектов поблизости с описаниями и изображениями из Википедии.

Приложение написано на Go. Для композиции асинхронных операций используется RxGo v2, для настольного интерфейса — Fyne v2. Настройки API загружаются из окружения и файла `.env` через godotenv.

## Возможности

- Поиск адресов и именованных объектов через GraphHopper.
- Выбор одного из найденных вариантов локации.
- Получение текущей погоды по координатам.
- Поиск географически привязанных статей Википедии поблизости.
- Конкурентная загрузка описаний и миниатюр объектов с ограниченным числом обработчиков.
- Вывод общего результата после завершения загрузки.
- Отмена поиска и загрузки деталей, защита от отображения устаревших результатов.
- Выбор радиуса и максимального числа объектов.
- Сохранение радиуса и лимита средствами Fyne Preferences.
- Карточки объектов с изображением справа и ссылкой на статью.

Поиск Википедии не является специализированным каталогом достопримечательностей: результаты зависят от наличия статей с координатами в выбранном языковом разделе.

## Используемые API

| Сервис | Назначение | Авторизация |
| --- | --- | --- |
| GraphHopper Geocoding | Поиск локаций по тексту | Параметр `key` |
| OpenWeather Current Weather | Погода по координатам | Параметр `appid` |
| Wikipedia Action API, GeoSearch | Статьи рядом с координатами | Без API-ключа для публичного чтения |
| Wikipedia TextExtracts и PageImages | Описания и адреса миниатюр | Без API-ключа для публичного чтения |
| Wikimedia image servers | Загрузка миниатюр | Без API-ключа |

Для запросов к Wikimedia задаётся идентифицирующий приложение `User-Agent` с контактной информацией.

## Схема выполнения

```text
Строка поиска
      |
      v
GraphHopper -> варианты локаций -> выбор пользователя
                                      |
                  +-------------------+-------------------+
                  |                                       |
                  v                                       v
          OpenWeather: погода                    Wikipedia: поиск рядом
                  |                                       |
                  |                                  []PlaceRef
                  |                                       |
                  |                          Map + WithPool(N)
                  |                            описание + миниатюра
                  |                                       |
                  |                           []PlaceDescription
                  |                                       |
                  +-------------------+-------------------+
                                      |
                               ZipFromIterable
                                      |
                                      v
                                LocationInfo
                                      |
                                      v
                             Обновление интерфейса
```

`Defer` создаёт источники при подписке, `FlatMap` связывает зависимые операции, `Map` с `WithPool` ограничивает конкурентность загрузки описаний. Результаты описаний собираются через `BufferWithCount` с проверкой полноты, затем сортируются по расстоянию. Пустой список мест передаётся отдельным элементом потока и не уничтожает результат объединения.

Ограничение пула — это ограничение числа одновременно выполняемых обработчиков, а не количества запросов в секунду.

## Требования

- Go, совместимый с зависимостями в `go.mod` и `go.sum`.
- Для GUI: C-компилятор, графические библиотеки разработки и работающая графическая сессия.
- Доступ к внешним API и серверу миниатюр Wikimedia.
- Ключи GraphHopper и OpenWeather с доступом к используемым методам.

Зависимости Fyne для Linux зависят от дистрибутива. Официальная инструкция: https://docs.fyne.io/started/quick/

Для Fedora, если линкер сообщает `cannot find -lXxf86vm`, установите:

```bash
sudo dnf install libXxf86vm-devel
```

Этот пакет устраняет конкретную ошибку отсутствия `libXxf86vm`; полный набор графических зависимостей смотрите в инструкции Fyne.

## Подготовка

Все команды ниже выполняются из каталога `task3`, содержащего `.env` и каталоги `cmd`, `internal`.

```bash
cp .env.example .env
```

Заполните ключи и укажите настоящий контакт в `WIKIPEDIA_USER_AGENT`. Затем загрузите Go-зависимости:

```bash
go mod download
```

Повторно выполнять `go mod init` не нужно. Если модуль расположен в родительском каталоге, Go использует его; файл `.env` всё равно ищется относительно текущего рабочего каталога процесса.

## Конфигурация

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `GRAPHHOPPER_API_KEY` | Обязательный ключ геокодера | Нет |
| `OPENWEATHER_API_KEY` | Обязательный ключ погоды | Нет |
| `WIKIPEDIA_USER_AGENT` | Обязательный идентификатор приложения и контакт | Нет |
| `GRAPHHOPPER_GEOCODING_URL` | Endpoint поиска локаций | `https://graphhopper.com/api/1/geocode` |
| `OPENWEATHER_WEATHER_URL` | Endpoint текущей погоды | `https://api.openweathermap.org/data/2.5/weather` |
| `OPENWEATHER_GEOCODING_URL` | Сохранённая настройка старого геокодера; в основном поиске не используется | `https://api.openweathermap.org/geo/1.0/direct` |
| `WIKIPEDIA_API_URL` | Языковой раздел и endpoint Википедии | `https://ru.wikipedia.org/w/api.php` |

URL хранятся без ключей и query-параметров. Параметры конкретных операций добавляют API-клиенты.

`godotenv.Load` не перезаписывает уже существующие переменные окружения. Отсутствие `.env` допустимо, если все обязательные настройки переданы через окружение. Ошибки чтения или синтаксиса файла приводят к ошибке запуска.

В текущей реализации следующие параметры задаются в коде, а не через `.env`:

- `HTTPTimeout`: 10 секунд на HTTP-запрос.
- `OperationTimeout`: 30 секунд на операцию.
- `DetailsWorkers`: 4 обработчика описаний.
- Начальный радиус: 5000 метров.
- Начальный лимит: 10 объектов.

Сохранённые корректные значения Fyne Preferences имеют приоритет над начальными радиусом и лимитом. Размер пула остаётся настройкой приложения.

Не публикуйте `.env` и не выводите полный URL запроса с ключом в лог.

## Запуск

### Графический интерфейс

```bash
go run ./cmd/gui/
```

1. Введите название места или адрес.
2. Нажмите «Найти» или Enter.
3. При необходимости настройте радиус и лимит объектов.
4. Нажмите «Выбрать» рядом с подходящим вариантом.
5. Дождитесь погоды и карточек мест.

Новые параметры применяются при следующем выборе локации. Уже запущенная загрузка использует собственный снимок настроек. Кнопка «Отменить» прерывает актуальную операцию. Изображения отображаются справа от описаний; ссылка открывает статью в браузере.

### Консольная точка входа

```bash
go run ./cmd/console/
```

Содержимое консольного сценария зависит от текущего `run.go`: он может использоваться для полного сценария либо диагностического запроса превью выбранной статьи. Основной пользовательский сценарий реализован в GUI.

### Сборка GUI

```bash
mkdir -p bin
go build -o bin/places ./cmd/gui/
./bin/places
```

Запускайте бинарный файл из каталога с `.env` либо передавайте настройки через окружение.

## Структура проекта

```text
cmd/
  gui/           Создание компонентов и запуск GUI
  console/       Консольный сценарий и диагностика
internal/
  config/        Загрузка и проверка конфигурации
  model/         Внутренние структуры данных
  api/           HTTP-клиенты и преобразование JSON
  service/       RxGo-операции и общий конвейер
  ui/            Окно, обработчики, карточки и настройки
```

UI не выполняет HTTP-запросы непосредственно в обработчиках кнопок. Ожидание результата вынесено в фоновую горутину; обновления виджетов передаются через `fyne.Do`. Идентификаторы операций защищают интерфейс от запоздалых результатов отменённых загрузок.

## Изображения

Описание и адрес миниатюры запрашиваются вместе через `prop=extracts|pageimages`. Затем обработчик скачивает и декодирует миниатюру до передачи результата в GUI.

Текущие ограничения загрузчика:

- Разрешён HTTPS и точные хосты `upload.wikimedia.org`, `thumb.wikimedia.org`.
- Автоматические редиректы общего HTTP-клиента отключены.
- Размер ответа: не более 4 МиБ.
- Размер изображения: не более 16 мегапикселей.
- Поддерживаются JPEG и PNG.

Отсутствие картинки или ошибка её загрузки не отменяет текстовое описание. Отмена всей операции при этом остаётся ошибкой отмены.

PageImages выбирает изображение статьи: это не обязательно фотография. Изображение выбранной основной локации пока проверяется отдельным методом `LoadLocationPreview` по названию статьи; его подключение к отдельной GUI-карточке не завершено. Точное название статьи и результат геокодера не всегда совпадают.

Для публичного распространения приложения требуется отдельно реализовать отображение авторства и лицензии изображений. Ссылка на статью сама по себе не заменяет сведения об атрибуции.

## Тесты

```bash
go test -v ./internal/api ./internal/service
go test -race ./internal/...
```

Повторная проверка конкурентности и отмены:

```bash
go test -race -count=20 ./internal/service
```

HTTP-тесты используют `httptest.NewServer`, сервисные тесты — подменные реализации интерфейсов. Они не требуют настоящих API-ключей и доступа в интернет.

Проверяемые сценарии включают успешные ответы, пустые результаты, HTTP-ошибки, повреждённый JSON, ошибки MediaWiki внутри HTTP 200, сборку общего результата, конкурентность и отмену.

Примеры сообщений `PASS` не являются частью гарантии: запустите тесты в своём окружении. Для проверки GUI с детектором гонок:

```bash
go run -race ./cmd/gui/
```

## Ограничения и соответствие условию

- Наличие объекта на карте не гарантирует результат поиска конкретного геокодера.
- Наличие статьи и её миниатюры зависит от выбранного языкового раздела Википедии.
- Ошибка погоды, поиска мест или текстового описания завершает общую операцию; ошибка фотографии сохраняется как частичная ошибка объекта.
- Перед выводом общего результата ожидаются также попытки загрузки миниатюр, поэтому картинки увеличивают общее время загрузки.
- Лимиты провайдеров и HTTP 429 необходимо учитывать; автоматические повторы и ограничение запросов в секунду пока не реализованы.
- HTTP-слой использует синхронный `net/http.Client.Do` внутри производителей и обработчиков RxGo. Сервис предоставляет асинхронный интерфейс, но это не превращает сам HTTP-клиент в библиотеку с отдельным асинхронным API. Допустимость этого решения по формальному требованию лабораторной нужно согласовать с преподавателем.
